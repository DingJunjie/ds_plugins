# Harness Todo · 1.1.0

正式 Harness 插件：左侧「待办清单」页面 + 聊天工具，共享本地 JSON 数据。保留优先级、截止日期、深浅色、勾选完成、筛选、拖拽及 Markdown 导出。

## 右上角浮窗

新增全局待办浮窗，默认位于窗口右上角。拖动标题栏移动，点击减号折叠、加号展开；位置和折叠状态保存在浏览器。标题栏聚焦后可用方向键移动，Home 回到右上角。窗口缩放时位置限制在可见范围。

浮窗显示未完成任务、优先级和截止日期，可直接勾选完成。底部左下角为「＋ 添加」按钮，点击后在其下方展开「新增待办」输入字段（可设优先级，默认中）；截止日期与重复请在完整清单页设置。右下角「完整清单 ↗」进入原页面。通过相同的认证 Host API 每约 2 秒同步，写入仍检查 revision。

左侧边栏「待办清单」那一行的右侧现在直接显示浮窗开关（一个小开关，点击切换浮窗显示，状态持久化）。实现上：Harness 侧栏菜单行本身不提供尾部插槽，因此开关渲染在图标内并用 `:has()` 绝对定位到行尾；侧栏折叠成窄栏时隐藏该开关，展开时才显示。开关为指针操作，屏幕阅读器因父级图标为 `aria-hidden` 而不朗读，属已知限制。

## 深色模式

Todo 页面默认**跟随 Harness 界面主题**：Harness 切到深色时页面同步变深色，切回浅色时同步变浅色。页面右上角的月亮/太阳按钮仍可手动切换；一旦手动切换，就固定为该主题，不再跟随，直到重新打开页面。判断依据是 Harness 根节点上的 `data-ds-dark-theme` 标记（同源 iframe，通过 MutationObserver 实时跟随）。

## 重复任务（页面新增）

页面新增时可选择「不重复 / 每天 / 每周」，选「每周」可勾选周一至周日任意组合。选重复后日期字段变为「开始」，留空默认从 Host 本地今天开始；重复任务不设独立截止日期。

重复任务按应做日期独立记录完成：今天勾完，下一个应做日重新出现，不会整条永久完成，也不会把错过的日期累积成补做任务。显示「↻ 每天 / 每周一、三、五」标记；导出 Markdown 会附加重复说明。

「清除已完成」只删除一次性已完成任务，重复任务保留；删除单个重复任务会先确认「删除整个重复任务及其完成记录？」。

## 聊天新增：先确认再写入

1. 用户直接要求添加事项。
2. `personal_todo_propose` 保存独立提案，不产生正式待办。
3. 助手在回复末尾展示完整事项、优先级、截止日期和确认编号，结束本轮。
4. 用户下一条直接回复「确认」或「确认 编号」，才能调用 `personal_todo_commit`。
5. Host 校验真实用户消息来源、消息顺序和助手展示过的事项/优先级/日期/编号，不能以模型提供的布尔值替代确认。

有多个提案时建议回复带编号的确认。新增参数需要修改时重新提案并确认。网页中点击「添加」属于用户直接操作，不经过聊天提案。

工具还包括 `personal_todo_list`、`personal_todo_pending`、`personal_todo_update`。修改先查询准确任务 ID 和 revision，有重名先问用户。日期只是截止日期，不是定时提醒。

## 存储与迁移

本地数据位置：`harness-todo-plugin/data/todos.json`（首次写入后创建，空清单不生成示例）。任务与提案保存于 Host，浏览器不再独占数据。同一个 Host 的页面和聊天共享清单，不意味着跨机器云同步。

旧插件使用的浏览器 `harness.todo.local.v1` 数据会在升级页面打开并连接成功后合并迁移；保留原 localStorage 备份，Host 确认迁移成功后才记录完成。采用稳定来源标记避免重复导入，不覆盖 Host 中已有任务。独立文件网页的数据因来源隔离不会自动读取。

页面挂载时每约 2 秒拉取快照；编辑或拖拽时暂停自动刷新。写入带 revision，冲突时显示错误而不是用旧列表覆盖新数据。断开时不虚报保存成功。

## 安装与开发

已通过 Plugin Manager 安装为 `harness-todo-local`，可在 Plugins 中停用/启用。是工作区本地链接，请勿移动或删除此目录；数据也在此目录，卸载或清理前请备份。依赖与当前 Harness `0.2.2-rc.1` 对齐，安装依赖时禁用了安装脚本。

构建：`python3 harness-todo-plugin/build.py`

测试：`node --test harness-todo-plugin/test/*.test.js harness-todo-plugin/frontend.test.mjs`

修改后重新构建、停用/启用插件并刷新原 Harness 页面；没有源码开发 watcher，不承诺自动重建。
