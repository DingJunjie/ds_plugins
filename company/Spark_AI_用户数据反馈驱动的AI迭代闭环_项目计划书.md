# 一、项目背景与目标

## 1.1 研发现状与痛点

当前研发团队在产品迭代过程中存在以下核心痛点，这些痛点本质上源于"人驱动"的传统范式在AI时代的局限性：

| **⚠ 痛点**<br>产品迭代依赖人工分析用户数据，PM需手动查看埋点数据、用户反馈、Bug报告，决策周期长（通常1-2周），且容易遗漏关键信号 | **✦ AI 如何解决**<br>PM Agent 7×24小时实时监控全量用户数据流，自动识别异常模式、高频问题和潜在需求，生成决策建议，将决策周期从"周"压缩到"小时" |
| --- | --- |

| **⚠ 痛点**<br>需求优先级排序主观性强，不同PM对同一组数据可能得出不同结论，缺乏数据驱动的客观决策框架 | **✦ AI 如何解决**<br>PM Agent基于多维数据（用户量级、影响范围、技术复杂度、业务价值）建立统一的优先级评分模型，输出可量化的决策依据，人工只需审核而非从零决策 |
| --- | --- |

| **⚠ 痛点**<br>从"发现问题"到"代码上线"链路过长，涉及多角色多轮沟通，信息在传递中失真，平均迭代周期远超预期 | **✦ AI 如何解决**<br>AI驱动的端到端闭环：数据采集→PM Agent决策→Coding Agent执行→自动化测试→上线，人工仅在关键节点审核，将全链路耗时缩短60%以上 |
| --- | --- |

| **⚠ 痛点**<br>产品上线后缺乏系统性的效果追踪闭环，功能上线即"失联"，难以快速验证假设并调整方向 | **✦ AI 如何解决**<br>闭环数据飞轮：每次上线自动触发效果监控，数据回流PM Agent形成"发布-监控-决策-迭代"的自动化循环，每一轮都让Agent决策更精准 |
| --- | --- |

## 1.2 项目目标

本项目旨在构建一套"AI原生"的产品迭代范式，核心目标如下：

*   **目标一：**搭建完整的"数据采集 → PM Agent决策 → 人工审核 → Coding Agent执行 → 工程师审核 → 上线 → 数据反馈"闭环系统
    
*   **目标二：**将产品迭代周期（从问题发现到修复上线）从平均2周缩短至2-3天
    
*   **目标三：**PM Agent决策准确率达到80%以上（以人工审核通过率衡量），实现"AI决策为主、人工审核为辅"
    
*   **目标四：**形成可复制的AI原生工作流范式，为公司其他团队提供可参考的转型样板
    
    ## 1.3 非目标（不做什么）
    
*   不替代PM的战略规划和创意性工作，AI Agent专注于数据驱动的执行层决策
    
*   不追求完全无人化，人工审核环节是设计中的安全网而非临时妥协

    # 三、初步技术路径
    
    ## 3.1 整体架构
    
    系统采用"数据驱动 + Agent协作 + Human-in-the-Loop"的三层架构，核心理念是让AI成为决策和执行的引擎，人作为质量守门员：
    
    _**数据采集层**__：前端埋点（用户行为、异常捕获）+ 后端数据（API日志、性能指标、错误追踪）+ 外部反馈（用户工单、评价）→ 统一数据管道_
    
    _**AI决策层**__： PM Agent（基于LLM +_ _memory system_ _+ 优先级评分模型）接收数据流，自动分类问题、评估优先级、生成决策建议（修Bug / 迭代优化 / 新功能提议）_
    
    _**审核层**__：人工PM通过Dashboard审核AI决策，可批准/拒绝/修改，审核结果回流__memory system__,_ _审核结果回流丰富Agent记忆，并周期性驱动决策策略优化_
    
    _**执行层**__：审核通过的决策自动分发给Coding Agent Teams，生成代码变更 → 工程师Code Review → 合并上线_
    
    _**反馈层**__：上线后自动触发效果监控，数据回流数据采集层，形成闭环飞轮_
    
    ## 3.2 技术选型
    
    | **层级** | **技术栈 / 工具** | **选型理由 / 备注** |
    | --- | --- | --- |
    | 前端埋点 | 自研SDK / GrowingIO / 神策 | 支持自定义事件和用户属性，数据实时回传 |
    | 数据管道 | Kafka + Flink / ClickHouse | 实时流处理 + OLAP分析，支撑秒级数据可用 |
    | PM Agent | LLM (Claude/GPT) + mem0 | LLM负责推理，记忆系统注入产品知识库上下文 |
    | 决策审核 | React Dashboard + 飞书/钉钉通知 | 可视化决策依据，移动端快速审批 |
    | Coding Agent | Claude Code / Codex / GLM | 支持多Agent并行，与Git工作流无缝集成 |
    | 效果监控 | 自定义指标 | 上线后自动对比核心指标变化 |
    
    ## 3.3 关键技术难点 & 应对思路
    
*   **难点一：PM Agent决策质量冷启动** → 应对：初期以规则引擎 + LLM结合的方式兜底，人工审核结果作为RLHF信号注入记忆系统持续优化
    
*   **难点二：多源异构数据的实时融合** → 应对：定义统一的事件schema，对数据做标准化清洗；Phase 1先接入最核心的2-3个数据源，逐步扩展
    
*   **难点三：Coding Agent输出代码质量不稳定** → 应对：限定Agent操作范围（harness engineering），必须通过自动化测试 + 工程师Code Review双重门禁
    
*   **难点四：闭环中各环节的可观测性** → 应对：每个环节都埋入trace ID，构建全链路追踪Dashboard，确保任何一环出问题可快速定位
    
    ## 3.4 待确认 / 待调研事项
    
*   PM Agent使用的策略和评价模型
    
*   Coding Agent与现有Git分支策略的最佳集成方式
    
*   决策分级的阈值标准（哪些可以自动执行，哪些必须人工审核）
    
*   不同功能agent之间的数据流通方式
    
    ## 3.5 交付形式
    
    最终交付一套完整的闭环系统，包含：数据采集SDK、PM Agent服务、审核Dashboard（Web端 + 移动端通知）、Coding Agent对接模块、效果监控面板。同时输出一份《AI原生产品迭代工作流范式指南》供其他团队参考。
