## 已理解的技术主线

### Host、MCP Client、MCP Server

```text
用户输入 → LLM 识别意图并提出工具调用
→ Host 解析、选择连接、检查白名单 / 参数 / 权限 / 确认策略
→ MCP Client / SDK 封装 JSON-RPC 2.0 的 tools/call 请求
→ MCP Server 执行工具，工具内部再访问业务 API / 数据库
→ 结果经 Client 回到 Host，Host 整理为工具结果消息
→ LLM 据实回答；失败不能降级为猜测
```

- LLM 的工具调用请求不是 MCP 请求。
- Host 负责受控执行；Client / SDK 负责协议封装和传输。
- JSON-RPC 的请求 ID 与模型工具调用 ID 可以不同。
- Host 不是天然自动发现任意接口；工具需要定义、注册和执行映射。
- 已有明确入口时可固定调用，不必让 LLM 选择。

### PDF AI-OCR 设计理解

- 上传 PDF → 应用保存并生成 file_id。
- 判断是否有文本层：可提取文本时优先提取；扫描件再调用 OCR。
- OCR 工具需要工具定义、参数 Schema、Host 注册和执行映射。
- Host 校验文件权限、页码、大小、费用和超时；工具读取 PDF 并调用 OCR 服务。
- 返回逐页文字和识别警告；LLM 再总结，不能把识别结果和总结混为一谈。

- 不先系统学完语法；用实例驱动。
- 看懂 AI 生成代码 → 改参数 → 改函数 → 增加校验 → 处理失败分支 → 自己写关键路径。
- 可将 Python 代码翻译成已有的 JavaScript 理解。
- 学习节奏不强制每天：一次投入 3 小时以上并跑通阶段性结果也可以收工。
- 预计：看懂基础代码 1—2 次；跑通知识库 2—5 次；能改关键逻辑约 1—2 周；形成可写进简历的个人项目约 3—6 周，取决于实际投入和调试。
